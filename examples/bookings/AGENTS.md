# bookings — agent guide

A simple appointment booking system. Customers book time windows on shared resources (rooms, equipment, staff). The database structurally guarantees no resource is ever double-booked.

This backend is built and operated with **dbmachine**: a Postgres database exposed through a self-documenting CLI. Invariants are enforced in the database, not in this prompt — you cannot corrupt data even if you issue a wrong command; the DB will reject it.

## How to operate this app

All commands accept `--json` and emit machine-readable JSON on stdout.

```
dbmachine inspect                 # overview of entities & operations
dbmachine describe <entity>       # full schema for one entity
dbmachine create <entity> --json '{...}'
dbmachine list <entity> [--where col=val] [--limit N]
dbmachine get <entity> <id>
dbmachine update <entity> <id> --json '{...}'
dbmachine do <operation> --json '{...}'   # typed custom actions
dbmachine query --sql 'SELECT ...'        # read-only SQL / views
dbmachine import <file> --entity <entity> # CSV/JSON/Excel ingest
dbmachine audit [--entity <entity>]       # change history
```

**Pull only what you need.** Don't read the whole schema up front — run `dbmachine describe <entity>` for the task at hand.

## Entities

- **`customer`** — A person who books appointments. → `dbmachine describe customer`
- **`resource`** — A bookable resource such as a room, table, or staff member. → `dbmachine describe resource`
- **`appointment`** — A booking of one resource for one customer over a time window. → `dbmachine describe appointment`

## Operations (beyond CRUD)

- **`confirm_appointment`** — Confirm a pending appointment, moving it to the confirmed state. (inputs: appointment_id)
- **`cancel_appointment`** — Cancel an appointment, freeing the resource's time window. (inputs: appointment_id)

## Views (read-only, for analytics/BI)

- **`upcoming_appointments`** — All confirmed appointments starting in the future, soonest first. → `dbmachine query --sql 'SELECT * FROM upcoming_appointments'`

## Guarantees

- Required fields, types, enums and uniqueness are enforced by Postgres.
- Structural invariants (e.g. exclusion constraints) make illegal states impossible.
- Every write is recorded in an audit log (`dbmachine audit`).
- The spec (`app.dbm.yaml`) is the source of truth — change it, then `dbmachine migrate`.
